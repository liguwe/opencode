# opencode 工程目录概览

这份文档只解决一个问题：先从目录结构上看清 `opencode` 这个工程大概怎么组织。

`opencode` 是一个 Bun + TypeScript monorepo。它不是单一 CLI 包，而是一组围绕 AI Coding Agent 的产品包：CLI/TUI 运行时、核心状态与数据库、模型 Provider、Web/桌面/App UI、SDK、插件、企业/Slack/统计等外围产品。

## 顶层结构

```text
opencode/
|-- package.json             # Bun workspace + Turbo 任务入口
|-- bun.lock                 # Bun 锁文件
|-- turbo.json               # monorepo task pipeline
|-- tsconfig.json            # 根 TypeScript 配置
|-- README.md                # 当前保留的中文 README
|-- AGENTS.md                # Agent 协作规则
|
|-- packages/                # 主 workspace，核心代码都在这里
|-- sdks/                    # 外部 SDK，例如 VSCode
|-- specs/                   # 协议/存储规格
|-- script/                  # repo 级脚本
|-- github/                  # GitHub 自动化相关包
|-- infra/                   # 基础设施配置
|-- nix/                     # Nix 相关配置
|-- patches/                 # Bun patchedDependencies 补丁
|-- perf/                    # 性能实验/记录
|
|-- .opencode/               # 本仓库自己的 opencode 配置、agent、skill、plugin
|-- .github/                 # GitHub workflow/action/issue template
|-- .husky/                  # Git hook
|-- .vscode/ .zed/           # 编辑器配置
```

顶层 `package.json` 说明这个工程的基本技术栈：

```text

  +-- workspaces: packages/console/*
  +-- workspaces: packages/stats/*

  `-- package-level tasks

TypeScript
  |
  +-- Effect
  +-- Hono

```

## 主包：packages/opencode

`packages/opencode/` 是现在读源码的第一入口。它对应用户运行的 `opencode` 命令，也包含 Agent 运行时的大部分实现。

```text
packages/opencode/
|-- package.json
|-- bin/opencode                  # 发布后的 bin 入口
|-- src/index.ts                  # yargs CLI 总入口
|-- src/cli/                      # CLI 命令、TUI、run runtime
|-- src/session/                  # session/message/prompt/LLM 请求/上下文压缩
|-- src/tool/                     # 内置工具与工具注册
|-- src/permission/               # 权限评估
|-- src/server/                   # HTTP server、事件、共享 UI/TUI 控制
|-- src/provider/                 # provider 配置/选择
|-- src/agent/                    # agent 定义与 prompt
|-- src/config/                   # 配置加载
|-- src/project/                  # 项目实例上下文
|-- src/storage/                  # 存储
|-- src/plugin/                   # 插件加载
|-- src/mcp/                      # MCP 集成
|-- src/lsp/                      # LSP 集成
|-- src/shell/ src/pty/           # shell/伪终端执行
|-- src/patch/                    # patch 处理
|-- src/skill/                    # skill 机制
`-- test/                         # 对应模块测试
```

### CLI 命令入口

关键文件：

- `packages/opencode/src/index.ts`
- `packages/opencode/src/cli/cmd/run.ts`
- `packages/opencode/src/cli/cmd/tui/*`
- `packages/opencode/src/cli/cmd/run/*`

启动链路：

```text
terminal
  |
  |  opencode [args]
  v
packages/opencode/bin/opencode
  |
  v
packages/opencode/src/index.ts
  |
  +-- init log / heap / env
  +-- one-time database migration
  +-- yargs command registry
  |
  +--> run
  +--> serve
  +--> tui thread / attach
  +--> mcp
  +--> agent
  +--> providers / models
  +--> import / export / session
  +--> debug
  `--> other commands
```

`src/index.ts` 更像 Node CLI 里的总路由器：初始化环境，然后把命令交给各个 `cli/cmd/*` 模块。

## run 命令和交互模式

`packages/opencode/src/cli/cmd/run.ts` 是 `opencode run` 的入口。它显式支持几种模式：

```text
opencode run
  |
  +-- non-interactive
  |     |
  |     +-- send one prompt
  |     +-- stream events to stdout
  |     `-- exit when session idle
  |
  +-- interactive local: --interactive
  |     |
  |     +-- boot in-process server
  |     +-- start split-footer TUI runtime
  |     `-- user keeps chatting
  |
  `-- interactive attach: --interactive --attach
        |
        +-- connect to running opencode server
        `-- run TUI against remote server
```

对应目录：

```text
src/cli/cmd/run/
|-- runtime.ts                  # 交互运行时主入口
|-- runtime.boot.ts             # runtime boot 相关
|-- runtime.lifecycle.ts        # 生命周期
|-- runtime.queue.ts            # 输入/事件队列
|-- runtime.stdin.ts            # stdin 处理
|-- stream.ts                   # event stream
|-- stream.transport.ts         # stream transport
|-- session-data.ts             # session 数据
|-- session-replay.ts           # session replay
|-- tool.ts                     # TUI 内工具展示
|-- footer.*.tsx                # 底部输入/权限/菜单/问题/子 agent UI
|-- scrollback.*                # 历史输出区域
|-- theme.ts
`-- types.ts
```

交互态可以按这个模型理解：

```text
keyboard/stdin
  |
  v
runtime.stdin
  |
  v
runtime.queue
  |
  v
runtime / lifecycle
  |
  +--> session prompt
  +--> permission question
  +--> tool result
  +--> stream event
  |
  v
OpenTUI / Solid TUI
  |
  +-- scrollback
  +-- footer prompt
  +-- permission prompt
  +-- menu / subagent / command
```

## Session / Agent Loop 大致位置

关键目录：

```text
src/session/
|-- session.ts             # session 信息、创建/恢复/分叉/持久化
|-- message.ts             # message 模型
|-- message-v2.ts          # v2 message 模型
|-- prompt.ts              # prompt 组装
|-- processor.ts           # session 处理流程
|-- llm.ts                 # LLM 调用入口
|-- llm/                   # AI SDK/native request/runtime
|-- tools.ts               # session 可用工具
|-- compaction.ts          # 上下文压缩
|-- overflow.ts            # token overflow 处理
|-- summary.ts             # session summary
|-- todo.ts                # todo 状态
|-- system.ts              # system prompt 相关
`-- prompt/*.txt           # 不同模型/agent 的提示词模板
```

可以先把 Agent Loop 理解成：

```text
user input
  |
  v
Session prompt builder
  |
  +-- project instructions
  +-- agent prompt
  +-- model-specific prompt
  +-- previous messages
  +-- tool definitions
  |
  v
LLM request
  |
  v
model response stream
  |
  +-- assistant text
  +-- tool call
  +-- reasoning/status
  |
  v
tool execution / permission
  |
  v
append message parts
  |
  v
continue until idle / stop
```

这部分和 Codex Rust 里的 `Agent Loop + Thread/Session + Tool Call` 是同一类问题，只是 opencode 用 TypeScript、Effect、AI SDK、SQLite 来组织。

## Permission / Sandbox

关键目录：

```text
src/permission/
|-- index.ts
|-- evaluate.ts
`-- arity.ts
```

opencode 的权限模型不像 Codex Rust 那样首先从 OS sandbox 视角切入；它更像在工具执行前做一层策略评估和交互确认：

```text
tool wants action
  |
  v
Permission.evaluate(...)
  |
  +-- allow
  +-- ask
  `-- deny
        |
        v
TUI footer.permission / question
        |
        v
user decision
        |
        v
continue tool execution or stop
```

`opencode run --dangerously-skip-permissions` 这类参数也在 `run.ts` 里出现，说明权限策略和运行模式强相关。

## 和 Codex CLI 的第一层对照

```text
Codex CLI
  |
  +-- codex-cli/          npm wrapper, very thin
  +-- codex-rs/           Rust native CLI/TUI/agent core

opencode
  |
  +-- packages/opencode/  TS/Bun CLI/TUI/agent core
  +-- packages/core/      shared state/database/model foundation
  +-- packages/llm/       provider/protocol abstraction
  +-- packages/app/web/desktop/ui
```

最明显的差异：

```text
Codex:
  npm wrapper -> Rust native binary -> CLI/TUI/Agent

opencode:
  Bun package -> TypeScript runtime -> CLI/TUI/Server/Agent
```

opencode 的 monorepo 更像一个完整产品工程：CLI、TUI、Web、Desktop、SDK、插件、Provider、数据库和云端/企业能力都在一个 workspace 里。读源码时不要只看 `packages/opencode`，但第一阶段应该以它为主线，再向 `core`、`llm`、`app` 展开。

## 建议阅读顺序

```text
1. packages/opencode/src/index.ts
   |
   `-- 看 CLI 命令如何注册

2. packages/opencode/src/cli/cmd/run.ts
   |
   `-- 看 run 命令如何分 interactive / non-interactive

3. packages/opencode/src/cli/cmd/run/runtime.ts
   |
   `-- 看 TUI 运行时如何驱动输入、事件、session

4. packages/opencode/src/session/
   |
   `-- 看 Session、Message、Prompt、LLM 请求怎么建模

5. packages/opencode/src/tool/registry.ts
   |
   `-- 看内置工具和插件工具如何统一成 Tool.Def

6. packages/opencode/src/permission/
   |
   `-- 看工具执行前如何 allow / ask / deny

7. packages/core/src/database + session + project
   |
   `-- 看状态怎么落 SQLite、怎么迁移

8. packages/llm/src/
   |
   `-- 看 provider/protocol 如何接入不同模型
```

第一阶段不要被 `app/web/desktop/enterprise/stats` 分散注意力。它们重要，但对“攻克 Code Agent CLI 骨架”来说，主链路还是：

```text
CLI entry -> run command -> runtime -> session -> llm -> tool -> permission -> event/storage
```
